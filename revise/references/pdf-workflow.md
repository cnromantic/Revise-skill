# PDF 论文处理规则

处理 `.pdf` 输入时，默认采用“复制源 PDF 后就近批注”的保守流程。

## 一、文件优先级

1. 处理 PDF 前，先判断同一目录中是否存在同主名 `.docx` 或 `.doc`。
2. 如果存在同篇 Word 文件，默认跳过 PDF，只处理 Word。
3. 跳过 PDF 时，在修改说明、批量汇总或处理日志中写明：`已发现同篇 Word 文档，默认以 Word 为准，PDF 未处理。`
4. 无法确定是否为同一篇论文时，不自动跳过，应列入人工确认或按用户指定处理。

## 二、复制后处理

1. 保留源 PDF，不覆盖。
2. 先复制源 PDF 为 `论文题目-修改稿.pdf`，再在副本上添加批注或高亮。
3. 未真正替换 PDF 正文时，只能称为“批注式修改稿”，不得称为“已完成正文替换”。
4. 扫描件或无文本层 PDF 不默认强制 OCR；如果用户未授权 OCR，输出页面级建议并在修改说明中说明限制。

## 三、文本提取与定位

处理前判断页数、是否加密、是否扫描件、是否有可提取文本层，以及当前环境可用的 PDF 工具。

优先使用 PyMuPDF（`fitz`）：

1. 用 `doc = fitz.open(source_pdf)` 读取 PDF。
2. 用 `page.get_text()` 提取文本。
3. 对可定位文本，使用 `page.search_for("问题短语")` 定位坐标。
4. 找到多个匹配位置时，结合页码、上下文和段落顺序选择最接近的问题位置。
5. 不能精确定位时，在对应页添加页面级批注，并在修改说明中标注“页面级批注”。

## 四、就近批注式修改稿

就近批注式修改稿应尽量接近人工 PDF 批注效果：

1. 在问题文字下方或右侧附近添加黄色批注框。
2. 批注框离问题位置不要太远。
3. 批注框可以遮住附近不需要修改的普通文字或图表，但不得遮住需要修改的问题文字。
4. 批注框使用黄色背景和清晰边框。
5. 批注内容要短，说明问题和建议改法。
6. 支持箭头或短线时，用箭头或短线指向问题文字。
7. 对无法定位到精确坐标的问题，在对应页添加页面级批注，并在修改说明中写明限制。
8. 如果只是批注而未替换正文，不得写成“已完成正文替换”。

所有逐项建议和可替换文本都合并写入修改说明，不再单独输出额外 Markdown 文件。

## 五、输出文件

PDF 只输出 3 个文件：

```text
论文题目-修改稿.pdf
论文题目-修改说明.md
论文题目-修改说明.pdf
```

## 六、验收要求

完成 PDF 处理后检查：

1. 源 PDF 未被覆盖。
2. `论文题目-修改稿.pdf` 已生成。
3. 批注尽量靠近问题位置，且未遮挡需要修改的问题文字。
4. 页面级批注、扫描件、无文本层、无法定位等限制已写入修改说明。
5. 未真正替换正文时，没有声称已替换正文。
6. 如果因同篇 Word 存在而跳过 PDF，汇总或日志已记录跳过原因。
