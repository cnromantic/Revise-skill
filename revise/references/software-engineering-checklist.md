# 软件开发类论文专项检查清单

系统设计与实现类、软件工程类、计算机应用开发类论文使用本清单。检查时要把论文中的需求、设计、实现、测试和截图作为同一条证据链看待。

## 一、系统一致性

1. 题目、系统名称、摘要、截图、结论、数据库表名和接口名是否指向同一个系统。
2. 是否出现无关模板残留，如其他系统领域、学生简历、课程、手机评论、食材类别等。
3. 技术路线、章节标题、图表和结论是否与论文题目一致。

## 二、摘要与研究任务

1. 摘要是否覆盖研究背景、技术路线、核心功能、测试或运行结果、应用价值。
2. 研究目标是否具体，是否能从后文需求、设计、实现和测试中得到支撑。
3. 结论是否基于已完成系统、测试结果和论文可见证据，不夸大未实现功能。

## 三、需求分析

1. 是否包含业务背景、用户角色、用例、功能需求、非功能需求和业务流程。
2. 功能需求是否能对应到系统设计、数据库表、页面截图和测试用例。
3. 非功能需求如安全、性能、可用性、兼容性是否有后文支撑。

## 四、系统设计

1. 是否包含总体架构、功能模块、数据库、接口、权限/安全、事务和异常处理。
2. 模块划分是否与需求一致。
3. 数据库表是否与功能和截图一致，字段名是否存在其他系统残留。
4. 接口说明是否包含请求方式、路径、参数、返回结果和错误处理。
5. 权限设计是否与用户角色、JWT、RBAC、菜单权限或数据权限说明一致。

## 五、系统实现

1. 是否说明前端页面/组件/API 调用，以及后端 Controller、Service、Mapper/Repository、Entity/DTO/VO 等分层。
2. 截图、代码说明、功能描述是否互相支撑。
3. 技术栈表述是否前后一致，例如 Spring Boot、MySQL、Vue.js、MyBatis、Redis、RESTful API、JWT、RBAC。
4. 章节中出现的版本号、框架名、数据库名和工具名是否与项目描述一致。

## 六、测试与运行证据

1. 测试是否覆盖登录、核心业务、异常流程、权限控制、接口、部署或运行证据。
2. “全部通过”等测试结论是否有表格、截图、日志、接口返回或明确测试记录支撑。
3. 测试用例是否包含输入、预期结果、实际结果和结论。
4. 测试结果是否与截图、数据库和功能描述一致。

## 七、图表与编号

1. 正文图表引用是否与图题、表题和编号一致。
2. 架构图、流程图、E-R 图、用例图、类图、时序图等是否与正文说明一致。
3. 表结构、接口表、测试表是否包含必要字段，且字段名称前后一致。

## 八、术语与写作规范

1. 按 `style-rules.md` 检查软件术语大小写和写法一致性。
2. 参考文献题名、代码、URL、数据库字段、文件路径不直接改。
3. 对无法确认版本或技术事实的内容，列入人工确认，不编造。
